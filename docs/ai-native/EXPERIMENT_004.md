# Experiment 004 — Concept references, Town DNA, and three causal towns

## Objective and hypothesis

Test the proposed image-reference workflow without confusing an unconstrained generated image with an executable RPG-Cobo map:

1. generate three deliberately different town concepts;
2. extract a shared visual vocabulary and three causal world grammars;
3. ground every noun and operation against the actual project assets and typed editor surface;
4. compile all three grammars through one data-driven generator into genuinely blank maps;
5. save, reload, validate, compare, autonomously select, refine, and playtest one result.

The hypothesis was that a generated reference can improve creative range if it is converted into a structured intermediate representation. A style-only JSON file was expected to be insufficient. The experiment therefore separates:

- `visual_style.json`: palette, composition, density, surface language, and controlled-imperfection rules;
- `world_grammar.json`: founding causes, historical phases, normalized routes, land uses, plots, props, and inhabitants;
- `rpgcobo_bindings.json`: real asset/material queries, decoded bounds, rotation limits, and explicit substitutions.

This run supports the hypothesis. The three maps are visibly and functionally different, and the strongest result is less axial than Linden Crossing. It also shows a remaining authorship boundary: the causal grammars were agent-authored structured plans, not yet generated by a reusable historical-growth simulator.

## Blank-map proof and authorship boundary

The driver refused to overwrite an existing map ID. It created `M978`, `M977`, and `M976` through `rpgcobo_project_create_blank_map`, opened each in the normal editor, and verified the same baseline contract before construction:

| property | required value |
|---|---:|
| Size | 128×64×128 |
| Occupied blocks | 16,384 |
| Free-block objects | 0 |
| Events | 0 |
| Ground layers | 1 |
| Source map/template | none |

The agent authored the concept prompts, structured styles, causal histories, normalized spatial specifications, binding translations, comparison, selection, and refinement. RPG-Cobo supplied the engine, renderer, editor semantics, block vocabulary, building/bridge/wall assets, character models, and runtime.

“From blank” therefore means no inherited terrain, roads, water, plots, props, events, or settlement layout. It does not mean that the source meshes, textures, characters, or materials were generated by the agent.

## Reference-to-engine grounding

The binding pass discovered all resources through semantic queries and inspected decoded MA bounds. Several concept nouns could be grounded directly:

| concept need | grounded result |
|---|---|
| Town hall/manor | `MA005`, 26×20×17 |
| Church | `MA008`, 14×23×19 |
| Shop | `MA006`, 16×13×16 |
| Warehouse | `MA010`, 18×12×10 |
| Long roadside inn mass | `MA004`, 24×12×10 |
| Stone bridge | `MA027`, 6×3×9 |
| Old retaining wall | `MA037`, 22×5×2 |
| Road, civic stone, water, dirt | authored block IDs discovered by type/model query |
| Lamps, flowers, benches, barrels, well, table, bushes, rocks, trees | authored free-block variations discovered by query |

The concepts also proposed carts, crates, sacks, sheds, fences, and varied building orientations. No matching authored semantic resources were available for several of those nouns, and non-zero MA rotation is unsafe in this native build. The binding layer therefore made explicit substitutions:

- freight activity became warehouse + paved yard + barrels + tables + worn service tracks;
- fence and boundary language became vegetation, dirt traces, one real retaining wall, and plot surfaces;
- many differently oriented small roofs became eight reusable silhouettes at rotation zero, while streets, setbacks, connectors, density, and land use carried the irregularity;
- the crossing stream was aligned so the real rotation-zero bridge could span it safely.

This is the central value of the intermediate representation: it preserves design intent while documenting which visual information could not survive grounding.

## One compiler, three grammars

`world_grammar.json` stores normalized coordinates in `[0,1]`. The driver derives block coordinates from actual map dimensions and decoded asset bounds, searches locally around each desired building anchor, enforces clearance and map margins, then compiles the specification into typed path, pond, fill, asset, forest, prop, event, spawn, validation, capture, and save operations.

The compiler code is unchanged across variants. What changes is the data grammar:

### Rillford — crossing grammar (`M978`)

Founding cause: a ford and later stone bridge concentrate movement across a stream.

Historical sequence:

1. chapel and footpath near the ford;
2. bridge fixes a crossing and bends the regional approach;
3. inn, shop, and market occupy the bridgehead;
4. housing follows both banks while an older western route fades.

The generated map contains an east-west curved watercourse, two bent bridge approaches, a real stone bridge, a market wedge, bank lanes, an abandoned trace, eight buildings, nine inhabitants/events, and partial bank groves.

### Oldcourt — accretion grammar (`M977`)

Founding cause: a planned civic court is later distorted by private additions.

Historical sequence:

1. hall, chapel, axial approach, court, and basin establish formal order;
2. commerce shifts toward lateral exits;
3. domestic lanes split southern plots at inconsistent depths;
4. a retaining-wall fragment survives the loss of the original enclosure.

The generated map contains a stone court with displaced basin, formal north axis, bent south approach, lateral accretion lanes, relocated market surface, wall fragment, eight buildings, nine inhabitants/events, and uneven edge planting.

### Barrelstead — trade-edge grammar (`M976`)

Founding cause: a regional road acquires a freight turnout, then other uses occupy its leftover land.

Historical sequence:

1. diagonal through-road crosses farm access;
2. inn and shop front the busy bend;
3. warehouse and loading yard expand behind commerce;
4. hall, chapel, houses, gardens, and an obsolete boundary adapt the remaining wedges.

The generated map contains a diagonal road, freight service track and yard, roadside market widening, civic spur, farm track, housing spur, obsolete south boundary, eight buildings, nine inhabitants/events, and land-use-specific prop clusters.

## Structural metrics

The driver calculated traceable structural measures before visual selection. These metrics deliberately do not pretend to measure beauty.

| metric | Rillford | Oldcourt | Barrelstead |
|---|---:|---:|---:|
| 15° path-direction bins | 5 | 6 | 4 |
| Mean authored curvature | 0.3533 | 0.2833 | 0.2700 |
| Building mirror-difference | 0.0519 | 0.0357 | 0.0747 |
| Connector-length coefficient of variation | 0.2087 | 0.1932 | 0.3319 |
| Functional prop categories | 6 | 6 | 7 |
| Initial prop acceptance | 71.43% | 87.50% | 85.00% |

These measures confirmed that the grammars differ, but both Rillford and Oldcourt reached the structural-diversity score ceiling. That exposed a useful limit: direction bins, curvature, asymmetry, and setback variance cannot determine whether large voids feel intentional or merely sparse. Visual review remained necessary.

## Autonomous visual comparison and selection

The agent evaluated the reloaded RPG-Cobo overviews—not the concept images—on causal legibility, coherent irregularity, historical signals, hierarchy, functional differentiation, density/proportion, and constraint translation.

| variant | visual score | strongest evidence | decisive weakness |
|---|---:|---|---|
| Rillford | 8.14/10 | River and real bridge make the founding cause immediately legible | Buildings are too dispersed; bridgehead pressure is weaker than the concept |
| Oldcourt | 7.20/10 | Court, basin, axes, and wall fragment establish an earlier formal phase | The large rectangular court still dominates; later growth reads as satellites |
| Barrelstead | 8.86/10 | Road, freight, market, civic, farm, domestic, and obsolete-boundary spaces behave differently | Freight yard is initially under-occupied |

Barrelstead was selected because its irregularity is the most causal rather than because it is the most picturesque. The conflict among through-movement, freight handling, inherited farm access, and leftover civic/domestic land remains readable in the constrained implementation.

## Selected refinement

The autonomous refinement intentionally preserved the winning grammar. It did not regenerate the whole town or conceal the comparison result.

Changes:

- removed the warehouse-authored below-map free block (`uid 30`);
- added a dirt wheel scar across the freight yard;
- placed two additional barrels, one table, and one yard lamp;
- added one market bench;
- retried domestic flowerbeds at collision-free positions.

All seven new prop placements were accepted. Final Barrelstead contains 143 free blocks and validates with zero errors.

## Runtime proof and timing failure

The first runtime attempt launched correctly and brought the player near the guide, but the driver invoked interaction while collision-aware movement was still active. The tool returned:

```json
{"accepted": false, "reason": "no reachable interaction target"}
```

One second later, the captured frame visibly showed the `Talk` prompt. This was a driver timing error, not evidence of an invalid guide or route. The failure was preserved in `runtime_attempts` rather than overwritten.

The driver was changed to poll until `interaction_target_event_id` is non-null before interacting. On the repeated proof:

- runtime reached `running=true` on `M976`;
- collision-aware movement acquired event `1000009`;
- interaction returned `accepted=true`;
- the runtime screenshot displayed “Welcome to Barrelstead”;
- the session stopped normally;
- save/reload completed;
- final validation returned zero errors.

Runtime artifact: `work/agent-output/M976-trade_edge-runtime.png`.

## What image generation contributed

The concept references materially improved the experiment in four ways:

1. **They proposed different organizing pressures.** River crossing, formal court, and freight turnout are not parameter changes to one road grid.
2. **They provided a vocabulary of useful voids.** Bridgehead, market wedge, loading yard, leftover green, obsolete boundary, and garden plots gave empty space a reason.
3. **They changed prop logic.** Decorations became land-use clusters rather than evenly distributed polish.
4. **They made loss visible.** Comparing reference and implementation reveals exactly where asset vocabulary, scale, rotation, and small-structure diversity constrain expression.

The images were least useful as literal inventories. They repeatedly suggested carts, sheds, fences, small annexes, and roof orientations that the project could not supply. Treating the image as direct geometry would have produced hallucinated assets or brittle approximations. Treating it as evidence for a causal grammar produced a traceable result.

## What this proves

- A reference-image workflow can transfer into a constrained editor when mediated by a semantic and executable intermediate representation.
- One compiler can construct three distinct from-blank towns by changing structured grammar data rather than branching into three task-specific generators.
- Simulated causes and historical phases produce more convincing irregularity than random coordinate noise.
- The same loop can include grounding, construction, safe rejection, save/reload, structural scoring, visual critique, selection, refinement, runtime movement, and interaction.
- Visual inspiration and constraint honesty are compatible; unavailable features can be translated explicitly instead of silently invented.

## What this does not prove

- General generation of Town DNA from arbitrary images. The extraction in this run was performed by the agent for three generated references.
- A reusable historical-growth simulator. The histories are structured specifications with authored normalized routes and anchors.
- Human-equivalent density or fine-grained plot design. All maps remain sparser than their references.
- Building orientation diversity, because MA rotation remains limited to zero.
- Persistent semantic identity after MA placement; planned source identity exists only in the trace.
- Physics-backed whole-town navigation or entrance access.
- Transfer to a different asset pack, editor, or engine.

## AI-native design lessons

1. **“Style JSON” should be decomposed.** Visual style, causal world grammar, and engine bindings have different change rates and failure modes.
2. **Reference extraction must include negative capability.** The binding artifact should state not only what exists, but which reference features cannot be expressed safely.
3. **History is an executable design prior.** Founding cause and phase sequence are more useful than a request for “organic” or “random” layout.
4. **Visual evaluation cannot be replaced by simple spatial metrics.** Oldcourt scored strongly on structural diversity while remaining visually dominated by its rectangle.
5. **Prop planning needs collision-aware local search.** Nine safe rejections show that normalized points alone are not enough when prefab assets bake undocumented free blocks.
6. **Runtime tools should synchronize on state, not elapsed time.** Interaction must wait for an acquired target rather than a fixed movement delay.
7. **Small-asset vocabulary limits spatial history.** Carts, fences, annexes, sheds, signs, and plot-boundary pieces would greatly increase character without requiring more primary buildings.
8. **Rotation remains disproportionately important.** Varied paths help, but parallel roofs continue to expose the prefab constraint.
9. **The future platform should retain the intermediate representation.** Founding cause, phase, district, route, plot, building, entrance, and prop cluster should survive as inspectable objects, not disappear into baked voxels.

## Strongest next experiment

Replace explicit normalized route/plot endpoints with a real historical-growth simulator. Its input should be only compact causes and constraints—for example crossing location, terrain/resource pressure, phase sequence, population targets, and available asset bindings. The simulator should generate persistent roads, plots, districts, and building instances, then use the same comparison and runtime loop demonstrated here. A second high-value test is revision: change Barrelstead's brief while preserving its regional road, residents, and freight identity.
